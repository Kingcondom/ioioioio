## 1. ขั้นตอน

1. ดู `tools/sets.json` หา `fileId` ของ deck ที่ได้รับมอบหมาย
2. อ่าน deck ด้วย `mcp__Google_Drive__read_file_content` (fileId) — ต้องโหลด schema ก่อนด้วย ToolSearch `select:mcp__Google_Drive__read_file_content`
   - ผลจะเป็นข้อความทีละสไลด์ `# n of N` · ถ้าดูเหมือนถูกตัด (เลขสไลด์ไม่ถึง N) ลอง `mcp__Google_Drive__download_file_content` ด้วย `exportMimeType: "text/plain"`
   - **เขียนโน้ตลง `notes/<set>_notes.md` ทันทีหลังอ่าน** — โครง outline ของ deck (หัวข้อ → ช่วงหน้าสไลด์) + ข้อเท็จจริงสำคัญ ตัวเลข เกณฑ์ ขนาดยา ที่สไลด์ให้ไว้ ทีละหัวข้อ (context อาจถูกย่อ ไฟล์ไม่หาย)
   - สไลด์ที่เป็นภาพล้วน/อ่านไม่ได้ → จดว่าหน้าไหน แล้วเขียนส่วนนั้นจากความรู้มาตรฐานพร้อมระบุว่าเสริม
3. แบ่ง deck เป็น **หมวด (lecture)** ตาม outline ของสไลด์ เช่น GI: `01 Esophagus & stomach` · `02 GI bleeding` · `03 Hepatitis` … ประมาณ 4–10 หมวดต่อ deck
   แต่ละหมวดมี **หัวข้อย่อย (section) = หนึ่งโรค/หนึ่งเรื่องตาม outline** เรียงตามสไลด์ ครบทุกหัวข้อใน outline ห้ามตกหล่น
4. เขียน `parts/<set>/<lec>.py` ทีละหมวด → `python3 tools/assemble.py <set>` → แก้จน check ไม่มี ✗ → ไปหมวดถัดไป
5. จบแล้วเขียน `notes/<set>_intro.txt` (2–3 ประโยค: deck นี้มีกี่หมวด เรื่องอะไร ลำดับที่แนะนำ) แล้ว assemble อีกรอบ
6. **ห้ามใช้ git ห้าม publish ห้ามแตะไฟล์ของชุดอื่น** — ผู้ประสานงานทำเอง

## 2. เนื้อหาหนึ่งหัวข้อย่อย (section)

ภาษาไทย ปนศัพท์อังกฤษแบบที่หมอไทยพูด ตรงตามสไลด์ก่อน แล้วอธิบายเพิ่มให้เข้าใจ:

- เปิดด้วย **นิยาม/ใครเป็น** แล้วไล่ **กลไก (pathophysiology) → อาการ/ตรวจร่างกาย → การวินิจฉัย (เกณฑ์ ค่า lab cut-off) → การรักษา (ยา ขนาด ระยะเวลาตามสไลด์) → ภาวะแทรกซ้อน/ส่งต่อ**
- ใช้ **ตาราง** เมื่อเปรียบเทียบโรคคล้ายกัน หรือเกณฑ์หลายข้อ · ใช้ `> ` เป็นกล่องเน้น (สิ่งที่ข้อสอบชอบออก/กับดัก)
- ตัวเลข เกณฑ์ ขนาดยา **ต้องตรงกับสไลด์** · ถ้าสไลด์เก่ากว่าแนวทางปัจจุบันชัดเจน ให้เขียนทั้งสองอย่างและบอกว่าข้อสอบน่าจะยึดอะไร
- เนื้อหาที่เติมเองนอกสไลด์ ให้ติดป้าย `(เสริม)` ท้ายประโยคหรือหัวข้อ
- `pearls` 3–5 ข้อ: ประโยคสั้นที่จำไปสอบได้เลย
- `nl`: รหัส นล. 2567 ที่ตรงเรื่อง หาด้วย `python3 tools/nl_find.py "regex"` (ใส่ทั้งชื่ออังกฤษและไทย) ใส่ 1–3 รหัส
- `source`: `"สไลด์ <deck> หน้า a–b"`
- `minutes`: เวลาอ่านโดยประมาณ

**ข้อจำกัดของ markdown ในหน้าเว็บ** (ผิดแล้วจะโชว์ดิบบนจอ)
- ไม่มี code fence ``` · ใช้หัวข้อ `###` `####` · ตาราง `|` · รายการ `-` หรือ `1.` · กล่องเน้น `> `
- ย่อหน้าถูกตัดเป็นบรรทัด → **ตัวหนาต้องเปิดปิดในบรรทัดเดียวกัน** (`**` ต้องเป็นคู่ในทุกบรรทัด)
- ห้ามมี `*` ติดตัวเลข/ตัวอักษรกลางคำ (เช่น HLA-B*27 → เขียน HLA-B27) · `*ตัวเอียง*` ใช้ได้
- ในตาราง ห้ามใช้ `|` ในข้อความ

## 3. ภาพ (figs) — วาดเมื่อภาพช่วยให้เข้าใจเร็วกว่าอ่าน

**ควรวาด** (เลือกเฉพาะที่คุ้ม ประมาณ 1 ภาพต่อ 2–3 หัวข้อ, หัวข้อที่เป็น approach/algorithm ควรมีเกือบทุกอัน):
- flowchart / algorithm การวินิจฉัย-รักษา (approach to …, การเลือกยาตามระดับ)
- กลไกโรค/เส้นทางสรีรวิทยา (เช่น RAAS, coagulation cascade, HPA axis, ตำแหน่งยาออกฤทธิ์ใน nephron)
- กราฟเวลา (serology ของ HBV ตามเวลา, troponin curve, ระยะ AKI)
- แผนภาพกายวิภาคแบบ schematic (ตำแหน่ง lesion ในสมอง → อาการ, ลิ้นหัวใจกับเสียง murmur, การกระจายผื่น)
- ตาราง 2 มิติที่อ่านง่ายกว่าเป็นภาพ (quadrant, spectrum)
**ไม่ต้องวาด**: สิ่งที่ตารางธรรมดาบอกได้ดีพอแล้ว · ภาพตกแต่ง · ภาพถ่าย/ภาพจริง

**กติกา SVG** (`tools/check.py` ตรวจให้)
- `<svg viewBox="0 0 W H">` W ประมาณ 640–760 · ไม่ใส่ width/height · ไม่มี `<style>` `<script>` `foreignObject` font-family
- **ห้ามใส่สีตรง ๆ** (#hex, rgb, fill="red") — ใช้ class ของธีมเท่านั้น จะได้อ่านออกทั้งโหมดสว่างและมืด:

| class | ใช้กับ |
|---|---|
| `box` | กล่องปกติ (พื้น surface ขอบเทา) |
| `sunk` | กล่อง/แถบพื้นหลังจาง |
| `acsoft` `c1soft` `c2soft` `oksoft` `badsoft` `misssoft` | กล่องเน้นสีอ่อน+ขอบสี (หลัก/ฟ้า/ม่วง/เขียว=ดีหรือปกติ/แดง=อันตราย/เหลือง=ระวัง) |
| `ac` `c1` `c2` `ok` `bad` `miss` | พื้นทึบสี (ตัวอักษรบนพื้นทึบใช้ `tw`) |
| `ln` `lnf` (ประ) `lna` `lnc1` `lnc2` `lnok` `lnbad` | เส้น/ลูกศร/เส้นกราฟ (fill none) |
| `arr` | หัวลูกศรใน marker |
| ข้อความ: ค่าเริ่มต้นสี ink 13px · `t2` เทาเข้ม · `t3` เทาเล็ก 11.5px · `tb` ตัวหนา · `ta` สีหลักตัวหนา · `tw` ตัวอักษรบนพื้นทึบ | |

- marker ลูกศร: `<defs><marker id="<section-id>-a" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse"><path d="M0 0L10 5L0 10z" class="arr"/></marker></defs>` แล้ว `marker-end="url(#<section-id>-a)"` — **id ต้องขึ้นต้นด้วย id ของ section** (ทั้งหน้ามีหลาย svg ห้ามชน)
- ข้อความใน SVG ไม่ตัดบรรทัดเอง → ใช้ `<tspan x=".." dy="16">` แบ่งบรรทัด · กว้างกล่องให้พอกับข้อความไทย (ประมาณ 7px ต่อตัวอักษรที่ 13px) · ตัวอักษร ≥ 11.5px
- จัดวางให้ไม่ทับกัน เส้นไม่วิ่งผ่านข้อความ ทุกอย่างอยู่ใน viewBox · กราฟต้องมีแกนและป้ายกำกับ
- วางในเนื้อหาด้วยบรรทัด `[[fig:<id>]]` (บรรทัดเดียวโดด ๆ) · fig ที่ไม่ถูกอ้างจะต่อท้ายเนื้อหาให้เอง
- `caption` หนึ่งประโยคบอกว่าภาพนี้อ่านอย่างไร

## 4. ข้อสอบท้ายหัวข้อ (items) — สไตล์ NL step 2

- **3–5 ข้อต่อหัวข้อ** (หัวข้อเล็กมาก 2 ข้อได้) ครอบคลุม: วินิจฉัย · investigation ที่ควรทำต่อ · การรักษา/ยา · ภาวะแทรกซ้อน/กับดัก
- โจทย์ **ภาษาอังกฤษ** clinical vignette สั้นแบบ NL (อายุ เพศ อาการ PE lab) ถามข้อเดียวชัด ๆ "What is the most likely diagnosis / most appropriate next step / drug of choice"
- 5 ตัวเลือกไม่ซ้ำ ทุกตัวต้องมีเหตุผลให้คนเลือก ถูกข้อเดียว
- `explain` **ภาษาไทย**: ทำไมตัวที่ถูกถูก (ไล่กลไก/เกณฑ์) แล้วบอกทีละตัวว่าตัวลวงผิดเพราะอะไร — **อ้างตัวลวงด้วยเนื้อหา ห้ามอ้าง "ข้อ A/B"** (ตำแหน่งจะถูกสลับ)
- `pearl` หนึ่งประโยค · `topic` สั้น ๆ · `ref` = `["สไลด์ <deck> หน้า n"]` · `nl` รหัสตรงเรื่อง
- ถ้าสไลด์มี **ข้อสอบเก่า/ตัวอย่างข้อสอบ** ของหัวข้อนั้น ให้เอามาเป็นข้อด้วย `kind="old"` และ `src="<ที่มาตามสไลด์ เช่น NL 2566>"` (เรียบเรียงใหม่ ตัวเลือกครบ 5 เฉลยอธิบายไทย) — ถ้าเฉลยในสไลด์ไม่ตรงแนวทางปัจจุบัน ให้บอกใน explain
- เขียนด้วย `mcq(...)` ใส่ตัวที่ถูกเป็นอาร์กิวเมนต์ `correct` — assemble จะสลับตำแหน่งให้เอง · ตัวเลือกที่เป็นลำดับธรรมชาติ (ตัวเลข/ระยะ) ใช้ `mcq_ordered(...)`
- id ข้อ: `<SET>-<lec>-<sec nn>-<q n>` เช่น `GI-03-02-1` (SET ตัวใหญ่) · id หัวข้อ: `<set>-<lec>-<nn>` เช่น `gi-03-02`
